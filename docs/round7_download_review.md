# ASTOP download draft: development review

Reviewed November 5, 2026. The supplied Korean/English desktop HTML and mobile previews can be implemented within the existing website. Round 7 explicitly requests feedback first; these draft downloads have not been published.

| Topic | Findings and recommendation |
| --- | --- |
| Installer hosting | Use versioned HTTPS objects in a dedicated release bucket or approved release host. Keep installers out of the website repository and the small edge-proxy disk. Publish a reviewed release manifest with version, platform, architecture, file size, checksum and URL; switch the current release atomically and retain the previous release for rollback. |
| macOS | Receive the final Developer ID-signed, notarized and stapled distribution from itriX. Verify that exact artifact before publication and calculate its checksum after packaging. Display “Apple notarized” only when verification succeeds; the website cannot notarize an unsigned file merely by displaying a label. See [Apple's distribution guidance](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution). |
| Windows | Receive the final signed installer and publisher identity. Test a browser-downloaded copy on a clean supported Windows system. Signing does not guarantee that SmartScreen reputation warnings disappear. Do not label unsigned files “Code signed” or make disabling protection a normal installation step. See [Microsoft's SmartScreen guidance](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation). |
| Access | IWL/itriX must choose public download or approved PoC participants. If restricted, enforce authorization at the download service and use short-lived links; hiding a button is insufficient. A submitted Google Form alone does not establish approval. |
| System information | Confirm Windows/macOS minimum versions, Intel/Apple Silicon/other supported architectures, RAM, storage, dependencies and permissions. Browser OS detection is only a convenience: keep manual selection and avoid guessing CPU compatibility. The draft currently shows the Windows “Recommended for this PC” badge statically. |
| Checksums | Replace the placeholder with the checksum of the published bytes. “Copy” is currently a styled span, not a working control. Implement a keyboard-operable button, success/failure feedback and selectable full hash text. |
| Mobile | Keep the proposed computer-download message; implement “Copy page link” as a real button with clipboard fallback. The three top CTAs can remain in one row, but English labels must stay legible at 390px and enlarged text sizes. Confirm popup focus, Escape/close behavior and screen-reader labeling. |
| Guide and releases | The installation guide, release notes and installer links currently point back to #download. Supply actual bilingual guide content, first-run steps, uninstall/update guidance, known limitations and support contact before activating them. |
| Existing website alignment | Use the current Ask itriX name and preserve the working home chat navigation; retain the approved language-specific PoC forms, current footer and cookie controls. The draft still uses the old Ask X label and omits Cookie settings. These draft regressions should not replace already approved navigation. |
| Commercial wording | “Free download” is a draft claim. Confirm whether this means a free installer, free evaluation or unrestricted free use. Confirm license and PoC conditions before publishing; no price or entitlement can be inferred from the design. |
| Privacy and logging | Agree whether to count download requests and what security logs are retained, who can access them and for how long. A request count is not a successful installation count. Update approved privacy/license wording to describe the actual release process; do not introduce extra tracking by default. |

Release handover needed: approved page/copy; launch date; final installer files and verification evidence; version/architecture/system requirements; license/access decision; guide and release-note content; hosting owner; release/rollback owner. Until supplied, the live chatbot points to ASTOP information and PoC applications and does not invent an available download.
